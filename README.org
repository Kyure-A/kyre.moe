* kyre.moe

Personal website and blog built with rshono and React Server Components, statically rendered for GitHub Pages.

** Screen Shot
[[file:./screenshot.png]]

** Highlights

- rshono + React Server Components + Hono
- Rspack, with every public route prerendered to HTML and Flight
- Panda CSS

** Dev

#+begin_src bash
  nix develop
  pnpm install
  pnpm dev
#+end_src

** Content helpers

#+begin_src bash
  nix develop
  pnpm content
#+end_src

Org articles are exported to Markdown, rendered to per-article JSON, and bundled as lazy server modules. Client navigation loads the prerendered Flight payload for each route. OGP images, sitemap.xml, robots.txt, and the prerender route list are generated by =pnpm content=. The development server watches articles and regenerates content when they change.

** Build and verify

#+begin_src bash
  pnpm build
  pnpm typecheck
  pnpm check:static
  pnpm lint
  pnpm start
#+end_src

The static site is emitted to =dist/client=. =pnpm start= serves those files locally; no application server is required in production. GitHub Actions builds and deploys that directory to GitHub Pages.

For GitHub Pages, =src/app/static-flight.ts= redirects rshono navigation requests to the generated =index.rsc= files and adapts their response MIME type. This is needed because Pages cannot serve HTML and Flight at the same URL based on the =RSC= request header. Browsers without the Navigation API use full page navigation.

=pnpm build:framework= runs only the framework build and static finalizer, using the already generated content and Panda snapshot. This is the command used for framework build comparisons.
